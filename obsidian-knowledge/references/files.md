# 文件输入

配图的取舍、落盘与嵌入规则只在 SKILL.md 的「配图流水线」维护；本节只写格式差异与提取契约。下文 `<Vault>` 指 SKILL.md 硬约束中的 Vault 根目录。

## MD、TXT

直接读取原件；默认 UTF-8，解码失败时确认原始编码，不使用忽略错误的解码，保留代码缩进。

图片引用要同时检查 Markdown `![]()`、引用式 `![说明][id]`、Obsidian `![[...]]` 与 HTML `<img>`，不能只识别一种。相对图片路径以原文所在目录为基准，不以当前工作目录为基准；有解释价值的图片按配图流水线处理。最终正文统一写 `![[assets/文件名]]`，遇到遗留的 `assets/...` 地址要在整理阶段补齐转换。

## PDF、DOCX

```bash
<python> <script> extract --source /path/input.pdf --output '<Vault>/00.草稿箱/原始资料/input-抽取'
```

输出目录必须是尚不存在的新目录，以免覆盖旧结果；同一原件已有结果时直接复用。成功时返回 `content`、`media`、`source_sha256`、`archive` 与 `warnings`：`--extracted` 直接传 `content` 的原值，不自己拼接路径。失败可能留下不完整目录，重试须换新目录名或先清理，不能把残留当成功输出。

把返回的 `source_sha256` 留在当前会话；提交前与 `preview` 中归档原件的哈希核对，原件变化需重新提取与预览。抽取内容只留在草稿箱原始资料目录，不写正式知识目录。

- PDF 用本地 PyMuPDF，按页保留文本与页码；可检测的表格另列在该页之后供核对，不把重复表格文本写进最终正文。栅格图提取到 `media`；矢量图、复杂布局、公式与代码缩进不能保证自动恢复，必须核对相关原页；不自动 OCR，无文本页标记待核查，全文无文本时停止并要求文本版。
- DOCX 用已安装的 Pandoc，保留常见标题、列表、代码、链接、表格与图片。复杂合并单元格、修订与公式需核对原件，转换成功不等于完整无损。抽取警告写入工具输出，不自动混入最终正文。
- 图片按内容哈希命名，避免不同资料的 `image1.png` 冲突。抽取稿把图排在页末不代表正文该放那里；确认整批图片都需要才整体入库，否则逐张挑选。
- 长资料按章节或页码读取，提取结果复用；重要修正与删除需回读对应原文，不要只用层层摘要作为正文依据。

## 依赖

PDF 使用本 Skill `.venv` 内固定版本 `PyMuPDF==1.26.7`，不需要模型服务或 OCR 依赖。DOCX 复用系统 Pandoc（本机 `/opt/homebrew/bin/pandoc`）。迁移机器后用 `python3 -m venv .venv` 重建并安装 `requirements.txt`，只为所需格式补依赖，不静默安装软件。MD、TXT、查重与保存不需要 PyMuPDF。
